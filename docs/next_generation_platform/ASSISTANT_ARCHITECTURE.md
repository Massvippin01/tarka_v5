## 1. System Vision & Foundational Guardrails

The **TARKA Assistant** is not a generic conversational chatbot. It is a governed, context-aware investigative copilot specifically engineered to assist digital forensics examiners, cyber-cell investigating officers (IOs), and public prosecutors in interpreting complex, multi-source digital evidence.

### Core Architectural Guardrails
1. **Evidence Isolation (DATA_ONLY):** Evidence ingested into TARKA is treated as passive, untrusted bitstreams. Content inside bank statements, PDFs, WhatsApp messages, or OCR text strings can **never** become executable agent instructions or override system rules (complete prompt injection defense).
2. **Grounding & Lineage Guarantee:** Every factual claim output by the assistant must cite a specific SHA-256 artifact hash. If evidence is insufficient, contradictory, or missing, the assistant must explicitly declare the limitation rather than infer or hallucinate an answer.
3. **Tri-State Epistemic Classification:** The assistant rigorously differentiates between:
   - **Observed Facts:** Directly proven by raw bitstream data (e.g. Finacle CBS statement line #14 debit).
   - **Inferences:** Hypotheses proposed by analytical heuristics (e.g. suspect entity clustering).
   - **Contradictions:** Formal discrepancies detected between independent sources (e.g. ₹25,000 screenshot vs ₹15,000 ledger debit).
4. **Mandatory Human Confirmation:** The assistant is architecturally prohibited from silently deleting evidence, altering ledger entries, merging identities, changing statutory case status, or issuing bank freeze notices. All consequential actions generate an explicit interactive confirmation prompt for the human officer.

## 3. Standard Forensic Response Format

Every forensic explanation generated by the assistant adheres to a strict, structured presentation standard:

```markdown
1. Direct Answer: Concise executive finding in the user's selected language.
2. Observed Facts (Bitstream Proven): Bulleted list of facts grounded in raw evidence.
3. Contradictions Detected: Bulleted list of mathematical or temporal conflicts.
4. Hypothesized Inferences: AI-proposed hypotheses requiring officer verification.
5. Evidentiary Citations: Interactive clickable badges linking to artifact SHA-256 hashes.
6. Suggested Next Action: Action button requiring explicit human confirmation.
```

### Example: Financial Discrepancy Inquiry in Tamil (`ta-IN`)
```
வங்கி கணக்கு அறிக்கை (ART-002) மற்றும் வாட்ஸ்அப் ரசீது (ART-004) இடையே ₹10,000 முரண்பாடு உறுதி செய்யப்பட்டுள்ளது. வங்கி லெட்ஜரில் ₹15,000 மட்டுமே பற்று வைக்கப்பட்டுள்ளது; ஆனால் ரசீது ₹25,000 கோருகிறது.

[Observed Facts]
• Finacle Ledger line #14 records debit of ₹15,000 (RRN 602811492015).
• Running balance mathematically conserves: ₹85,00,000 -> ₹84,85,000.

[Contradictions Detected]
• Bank debit ₹15,000 vs. Complainant receipt ₹25,000 (Gate I1 FAILED).

[Citations]
[ART-002-887B114A (SBI Finacle)]  [ART-004-6155034A (Receipt Screenshot)]

[Action Button: Inspect Row #14 in Ledger]
```

## 4. UI Ergonomics & View Modes

1. **Slide-Over Drawer Mode:** 540px width tactile side panel allowing investigators to inspect evidence while simultaneously reviewing the assistant's structured findings.
2. **Fullscreen Conversation Mode:** Expands to an immersive modal workstation for detailed multi-page forensic reports and evidentiary debates.
3. **Voice Interrogation Mode:** Seamless 1-click pivot to the real-time multilingual speech-to-speech modal (keyboard shortcut: `V`).
4. **Speech-Audio Playback:** Built-in speech synthesis with real-time waveform audio indicators and a one-click barge-in stop button.
