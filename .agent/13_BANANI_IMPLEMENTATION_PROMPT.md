# SentinelX --- Master Build Prompt

## EXECUTION MODE

Build SentinelX as a **real, coherent, production-oriented investigative
intelligence application**, not a collection of visual mockups.

The entire product must feel as though one senior enterprise
product-design and engineering team designed it.

### Absolute priorities

1.  Investigator usability
2.  Navigation clarity
3.  Evidence clarity
4.  Context preservation
5.  Responsive correctness
6.  Voice-assisted interaction
7.  Explainable intelligence
8.  Security and governance
9.  Visual precision
10. Feature depth without clutter

When forced to choose: - less cognitive load \> more features - clarity
\> visual spectacle - human control \> AI automation - evidence \> AI
confidence

## PRODUCT

Name: **SentinelX**

Description: **AI-Powered Criminal Network Analysis System**

SIH: **Smart India Hackathon 2026 · Problem Statement 26189**

Core workflow: **DISCOVER → CONNECT → VERIFY → EXPLAIN → DECIDE**

AI principle: **ML PROPOSES → EVIDENCE VERIFIES → HUMAN DECIDES**

## VISUAL

Dark enterprise intelligence workstation.

Use:
`#081018 #0D1721 #111E2A #243342 #F3F6F8 #9BAAB7 #31C4D8 #45C98A #E6B85C #E26D78`

No gradients, glassmorphism, neon, cyberpunk, 3D, decorative AI imagery,
rainbow charts or excessive animation.

## RESPONSIVE

Support 1280 → 1366 → 1440 → 1920 → 2560/4K → ultrawide → tablet →
mobile.

Support approximately 200% browser/UI zoom without critical breakage.

Do not merely shrink desktop. Recompose intelligently.

At 4K, expand useful investigation workspace while preserving readable
max widths.

At small widths, collapse secondary navigation and move contextual
information into drawers.

## APPLICATION SHELL

Use: - compact left navigation - global search - voice control -
user/access context - breadcrumbs - page identity - active workspace

Every major screen must be a real route or functional state.

No fake links. No dead buttons.

## NAVIGATION

Use: 1. primary navigation 2. breadcrumbs 3. contextual Back/Next

Preserve investigation context through navigation.

Example:
`Command Center → Investigation → Person → Phone → Relationship → Evidence`

Back follows the actual chain.

## INVESTIGATION WORKSPACE

Lenses: **Overview \| Network \| Timeline \| Map \| Evidence \| Entities
\| Findings**

Changing lenses preserves investigation identity.

Use progressive disclosure: **Preview → Expand → Full view**

## GRAPH

Entities: Person, Case, FIR, Phone, Device, Vehicle, Location,
Organization, Transaction, Document, Evidence, Event.

Relationships: Involved In, Contacted, Uses, Owned By, Located At,
Associated With, Transferred To, Mentioned In, Supported By,
Contradicted By, Occurred At, Related To.

Controls: search, expand, collapse, focus, isolate, shortest path,
common connections, compare, time and evidence filters.

Graph associations must never be presented as proof of guilt.

## EVIDENCE

Every important AI result must expose: - why - supporting evidence -
contradicting evidence - sources - confidence - status

## VOICE --- SIGNATURE EXPERIENCE

Create a restrained assistant named **Sentinel**.

It should feel like a competent investigation aide.

No giant avatar.

No mascot.

No theatrical voice.

Primary mode: push-to-talk.

Optional explicit investigation session.

Never silently listen by default.

State:
`OFF → ACTIVATED → LISTENING → TRANSCRIBING → UNDERSTANDING → EXECUTING → VERIFYING → RESPONDING`

Commands: - "Open the network." - "Show the timeline." - "Go back." -
"Focus on this phone." - "Show connections between these two people." -
"What evidence supports this?" - "What contradicts this?" - "Find
similar cases."

If ambiguous: ask for clarification.

For reversible actions, do not interrupt unnecessarily.

For consequential actions such as export, delete, permissions, sensitive
sharing and high-impact watchlist changes, require confirmation.

Every meaningful spoken result must have a visible UI anchor.

Architecture:
`Microphone → VAD → Streaming STT → Intent/Entity Parsing → Authorization → Tool Execution → Evidence Verification → UI Update → Streaming TTS`

Use provider adapters. Prioritize English and Kannada initially.

## TRUST

Separate: **Observation → Inference → Recommendation → Investigator
Decision**

Use evidence states: Corroborated, Supported, Partially supported,
Unverified, Contradicted, Insufficient evidence, Requires human review.

Never declare guilt.

## TECHNOLOGY

Frontend: Next.js, React, TypeScript, Tailwind CSS, AntV G6, MapLibre
GL.

Backend: Python, FastAPI, Pydantic, SQLAlchemy.

Data: PostgreSQL, Neo4j, S3-compatible object storage.

Search: OpenSearch where justified.

AI/ML: spaCy/transformers, entity resolution, anomaly detection, Neo4j
Graph Data Science, private/local LLM where required.

Events: Kafka for production-scale evolution where justified.

Deployment: Docker for prototype; Kubernetes/HA/observability/secret
management for production evolution.

CCTNS/ICJS and other government systems are integration targets, not
fabricated live connections.

## FINAL BUILD RULE

Do not build: **Dashboard + Graph + Chatbot**

Build: **Investigation → Search → Connect → Graph/Timeline/Map →
Evidence → AI Lead → Proof → Contradiction Check → Human Decision →
Audit**

Every click must be predictable.

Every destination must be intentional.

Every screen must remain understandable.

The investigator should stop thinking about the interface and start
thinking about the investigation.
